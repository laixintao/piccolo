The synthetic latest origin ran on controlplane port `15000`. It only accepted

## Fixes from validation

1. `latest` detection split the reference at the registry port's colon. It now
   checks the tag suffix of the repository name, including IPv6 registries.
2. The reverse proxy rejected valid `206 Partial Content` responses. Range
   responses now pass through and count as mirror hits.
3. A failed peer immediately committed `502` before another peer was tried.
   Failed attempts now leave the response untouched until a peer succeeds or
   all peers miss.
4. Code inspection after the deletion assertion found that missing blob
   metadata was mapped to `500`. Missing content now returns `404` and an INFO
   upload miss. A blob deleted between size lookup and opening also clears the
   obsolete Content-Length. Missing-content behavior passed VM verification;
   the size/open deletion race and storage errors have local regression coverage.
5. A local race-suite run exposed process-wide containerd ingest-lock collisions
   between parallel fixtures. Fixture ingest references now include each
   temporary store path.

## Deletion and containerd image aliases

The first last-copy deletion check saw HTTP `200`, not a missing-content
error: containerd had retained a CRI-managed image named by the config digest
in `k8s.io`. Its target was verified to be the test manifest. This remaining
image kept the content available in a configured namespace even after the
registry-named tag was deleted.

After removing that test alias, Pi returned `404 / INFO / miss`, while the
same image still existed in the excluded namespace. Discovery had already
withdrawn node01's registry-scoped advertisement and retained the other
holders. This distinguishes tag/advertisement removal from content garbage
collection; deleting a tag does not guarantee the blob disappears immediately.
